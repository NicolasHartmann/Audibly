# Sync between Windows and Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Listen on one device and continue at the same place on another; listening time and trophies count across devices.

**Architecture:** Each device writes one JSON file into a folder a cloud service keeps in sync and reads the files of the others. All logic lives in the platform-neutral library `Audibly.Sync`; the two apps only supply folder access, a settings store, their library and a few UI elements.

**Tech Stack:** .NET 8 library with System.Text.Json and xunit; Windows App SDK app (`Audibly.App`); .NET MAUI Android app (`Audibly.Mobile`) with the Storage Access Framework.

**Spec:** `docs/superpowers/specs/2026-11-15-sync-design.md`

## Global Constraints

- Without a chosen sync folder both apps behave exactly as before.
- The position never changes without the listener agreeing in a dialog.
- A device writes only its own file `audibly-sync/<deviceId>.json`.
- Sync never throws into playback and never blocks the UI thread; failures are logged and shown as a state in the settings.
- Own statistics (`stats.db`) are never modified by the sync; other devices are only added up for display.
- UI texts are English.

## Review Focus

- The sync folder disappears, is read-only or full while a book plays: playback and saving continue.
- Two devices with clocks a few minutes apart: an offer may appear or not, but the position is never changed silently.
- A book that exists on only one device: no offer, no crash, its listening time still counts in the totals.
- A cloud conflict copy or half-written file in the folder is ignored.
- Opening a book while the folder is slow (cloud placeholder files): the book opens at once, the question may come a moment later.

### Task 1: `Audibly.Sync` core — done

`DeviceState` and `DeviceStateFile` (format version 1, one file per device), `BookMatch` (same title and author, or same author and total length within 2 s), `SyncMerge.Offer` / `BuildState` / `Combine`, `ISyncFolder`, `DirectorySyncFolder`, `SyncService` (push and pull, never throws), `ISyncSettings`, `SyncDevice.GetOrCreateId`, `SyncSession` (throttled push, offer on opening a book, declined offers, combined statistics). Tests in `Audibly.Sync.Tests` (35).

**Interfaces the apps use:**

- `new SyncService(ISyncFolder folder, string deviceId, string deviceName, Func<DateTime> utcNow)`
- `new SyncSession(SyncService service, Func<Task<IReadOnlyList<LocalBook>>> books, Func<Task<StatsData>> ownStats, ISyncSettings settings, Func<DateTime> utcNow)`
- `Task SyncSession.PushAsync(bool force)`, `Task<PositionOffer?> OfferForAsync(Guid bookId)`, `void Decline(PositionOffer offer)`, `Task<StatsData> CombinedStatsAsync()`, `IReadOnlyList<DeviceState> Others`, `DateTime? LastSuccessUtc`, `string? LastError`
- `record LocalBook(Guid Id, string Title, string Author, double DurationSeconds, double PositionSeconds, double Speed, bool Completed, DateTime? LastPlayedUtc)` — `PositionSeconds` is the position in the whole book (`PlayerProgress.BookPositionMs / 1000`), `LastPlayedUtc` is null for a book never played on this device.
- `record PositionOffer(Guid BookId, string DeviceName, double PositionSeconds, double Speed, DateTime UpdatedUtc)` — apply with `PlayerProgress.Locate(sourceDurationsSeconds, PositionSeconds * 1000)`.

### Task 2: Windows app

**Files:** `Audibly.App/Services/SyncHost.cs` (new), `Audibly.App/App.xaml.cs`, `Audibly.App/Helpers/UserSettings.cs`, `Audibly.App/ViewModels/PlayerViewModel.cs`, `Audibly.App/Views/SettingsPage.xaml(.cs)`, `Audibly.App/Views/StatsPage.xaml.cs`, `Audibly.App/Views/TrophiesPage.xaml.cs`, `Audibly.App/Audibly.App.csproj`.

- Settings: "Sync folder" card with folder picker, the chosen path, last successful sync, the other devices found, and "Turn off".
- `SyncHost`: creates the `SyncSession` over a `DirectorySyncFolder` when a folder is set; maps the library to `LocalBook`; stores settings in `ApplicationData.Current.LocalSettings`.
- Push: forced on pause, on opening another book and on exit; unforced from the position handler while playing.
- Offer: after a book is opened, ask in a `ContentDialog` ("On {device} you were at {time} ({when}). Continue there?" with "Continue there" and "Stay here"); on accept seek there, on decline call `Decline`.
- Statistics and trophies pages show the combined statistics when sync is on.
- `DateLastPlayed` of a book is updated whenever its position is saved while playing, so the other device can tell which state is newer.

### Task 3: Android app

**Files:** `Audibly.Mobile/Services/SyncHost.cs` (new), `Audibly.Mobile/Platforms/Android/AndroidSyncFolder.cs` (new), `Audibly.Mobile/Services/PlaybackCoordinator.cs`, `Audibly.Mobile/Views/SettingsPage.xaml(.cs)`, `Audibly.Mobile/Views/LibraryPage.xaml.cs`, `Audibly.Mobile/MauiProgram.cs`, `Audibly.Mobile/Audibly.Mobile.csproj`.

- `AndroidSyncFolder : ISyncFolder` over a folder picked with the system folder dialog (persisted read and write permission), using `DocumentFile`.
- Settings: "Sync folder" with pick, state and "Turn off", like Windows.
- Push and offer at the same moments as on Windows; the offer is a `DisplayAlertAsync`.
- `DateLastPlayed` updated on every save while playing.

### Task 4: End-to-end check

Windows dev app and the virtual phone share one folder (the virtual phone's folder is copied with `adb` in both directions to stand in for the cloud): listen on one, open on the other, accept and decline the offer, check combined totals. Then the user tries a real OneDrive folder on the phone, which is the open risk named in the spec.
